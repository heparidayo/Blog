# 1. 컴퓨터 그래픽스
컴퓨터로 시각적 장면과 이미지를 표현하고 생성하고 처리하는 분야.   
여기서는 컴퓨터 그래픽스를 네 가지 관점으로 살펴보려한다.

- Scene Representation
- Rendering
- Image Quality \& Processing
- Learning-based Graphics

### 1-1. 장면 표현
장면을 데이터로 어떻게 표현할까?

\[명시적 표현]
- mesh: 정점과 면의 연결 관계로 물체의 표면을 표현
- point cloud: 점들의 집합으로 형태 표현
- voxel: 공간을 3차원 격자로 분할 표현
- 3DGS: 가우시안을 이용해 장면 표현

위 방식들은 기하 요소들을 명시적으로 저장한다.

\[암시적 표현]
- SDF
- NeRF: f(x, y, z, θ, φ) = (R, G, B, σ)

위 방식은 공간의 위치를 입력받아 값을 계산하는 함수로 장면을 표현한다.

대표적으로 SDF는 기하를 나타내는 함수,   
NeRF는 색상과 밀도를 나타내는 함수.

위에서 저장한 데이터를 특정 카메라 시점에서 어떻게 이미지로 바꿀 것인가?
여기서 렌더링이라는 개념이 등장한다.

### 2-2. 렌더링
이미지를 어떻게 생성할까?

- Rasterization: 3D 삼각형을 화면에 투영, 삼각형이 덮는 화면 샘플을 계산
- Ray Tracing: 광선을 추적하여 장면의 물체화의 교차 및 가시성 계산
- Volume Rendering: 공난 내부의 밀도, 색상, 흡수, 산란 등의 정보를 광선 경로를 따라 누적
- Splatting: 점이나 가우시안등의 기여를 화면에 투영하고 합성

참고로 이번 글에서는 Mesh 기반의 Rasterization 그래픽 파이프라인을 중심으로 다룬다.

### 2-3. Image Quality \& Processing 후처리
이미지 품질 개선 및 처리

- Anti aliasing: 계단 현상등의 샘플링 아티팩트 감소
- Denoising: 렌더링 과정에서 발생한 노이즈 제거
- Upscaling: 낮은 해상도 -> 높은 해상도 생성`
- Tone Mapping: HDR 색상 휘도 정보를 디스플레이에 표시할 수 있는 범위로 변환


### 2-4. Learning-based Graphics (신세대!)
딥러닝을 그래픽스의 장면 표현, 렌더링, 품질 개선에 어떻게 사용할까?

\[대표 사례]
- NeRF
- 3DGS
- DLSS

위와 같은 기술들이 기존 컴퓨터 그래픽스의 장면표현, 렌더링, 후처리 기술에 접목되어 발전하고 있다.


# 2. 이번 주제: Rendering Pipeline
컴퓨터 그래픽스에서는 3차원 Scene을 표현하는 방법도 다양하고, 이를 2차원 이미지로 만드는 렌더링 방법도 다양하다.
이번에는 그 중에서 Mesh기반 Scene 표현을 Rasterization Grapchis Pipiline 으로 렌더링 하는걸 중심으로 살펴보자.

3차원 공간에 존재하는 물체는 어떤 과정을 거쳐 2차원 화면에 표현되는걸까?

단순히 생각해보면..

3차원 정점의 좌표를 2차원으로 변환하면될거라 생각하기 쉽다. 

하지만, 실제로는 

- 어떤 물체가 카메라에 보이는가?
- 삼각형이 화면의 어떤 부분을 차지하는가?
- 각 부분은 어떤 색을 가져야 하는가?
- 여러 물체가 겹친다면 누가 앞에 있는가?

등을 계산해야 한다.

이러한 계산을 효율적으로 수행하기위해 그래픽스 시스템은 여러 단계로 나눠 처리하는데
우리는 이걸 "Graphics Pipeline" 이라고 한다.

이번 글의 목표는 삼각형 하나가 GPU에 입력되어 최종 이미지로 나타나는 전체 과정을 이해하는 것이다.
참고로, 각각의 단계를 일종의 함수처럼 `Input` -> `Operation` -> `Output` 의 순서로 접근하는걸 추천한다.
> 어떤 데이터를 입력받고(`input`), 어떤 연산을 수행하고(`operation`), 어떤 결과를 다음 단계에 전달하는가?(`output`)

그럼 이제 Vertex Processing 부터 Rasterization, Fragment Processing, Framebuffer까지의 흐름을 이해해 보자.


# 3. Overview
이번 글에서 다룰 파이프라인의 큰 흐름은 아래와 같다.

1. Vertex Input : 정점 데이터 입력
2. Vertex Shader : 정점 좌표 변환
3. Primitive Assembly \& Clipping : 삼각형 구성 \& 시야 밖 부분 제거
4. Perspective Divide \& Viewport : NDC \& 화면 좌표 변환
5. Rasterization : 삼각형이 덮는 화면 샘플 계산
6. Fragment Shader : 색상 등 결과 계산
7. Per-Fragment Operations : 깊이, 스텐실 검사 및 색상 합성    
*(`early depth test` 처럼 일부 검사가 fragment shader 전에 실행하기도 함)*
8. Framebuffer : 렌더링 결과 저장


# 4. Rasterization-based Graphics Pipeline
> essellation/Geometry Shader 등의 선택 단계를 건너뛴 OpenGL 좌표계 기준의 정통적인 렌더파이프라인이다.
## 4-1. Vertex Input


- Vrtex Buffer에 정점 속성을 읽어서 Vertex Shader에 전달
- { x,y,z, nx,ny,nz,tx,ty,tz, u,v, r,g,b,a, }
- 
- { P / N / uv / Color }
$$
\mathbf v_i=(\mathbf p_i,\mathbf n_i,\mathbf{uv}_i,\mathbf c_i,\ldots)
$$

## 4-2. Vertex Shader
- 위에서 전달해준 정점 속성
- Model, View, Projection 행렬 등 쉐이더 제공 데이터

- local 좌표에 MVP 순으로 연산 후 clip 좌표를 추출
- { P_clip } = { x, y, z, w }
- { uv, nxyz, rgba }
$$
\mathbf p_{\text{clip}}=(x_c,y_c,z_c,w_c)^T
$$
> 참고로 P 행렬은 FOV 해상도 Far/Near 등이 들려있음


## 4-3. Primitive Assembly & Clipping
`Primitive Assembly` 정점들을 묶어 primitive로 구성
`Clipping` primitive(triangle)을 카메라 시야에 맞게 자르기

- 위에서 전달된 Clip 정점 및 속성
- 정점 연결 정보 (ex: Triangle List)

$$
\boxed{
\begin{aligned}
-w_c&\le x_c\le w_c\\
-w_c&\le y_c\le w_c\\
-w_c&\le z_c\le w_c
\end{aligned}}
$$

- 클리핑된 삼각형들
- 각 정점의 속성



## 4-4. Perspective Divide & Viewport
실제 모니터 화면 좌표로 변환하는 과정
`Perspective Divide` NDC 변환

$$
\boxed{
\mathbf p_{\text{ndc}}=
\left(
\frac{x_c}{w_c},
\frac{y_c}{w_c},
\frac{z_c}{w_c}
\right)
}
$$

`Viewport` 실제 모니터 좌표 변환 (좌하단 x_0, y_0)

$$
\boxed{
\begin{aligned}
x_s&=x_0+\frac{x_{\text{ndc}}+1}{2}W\\[4pt]
y_s&=y_0+\frac{y_{\text{ndc}}+1}{2}H
\end{aligned}}
$$

- 실제 화면에 투영할 삼각형의 정보를 전달

## 4-5. Rasterization
점만있는 삼각형에서 fragment 생성

**입력**
- 삼각형
- 각 정점별 UV, Normal, Color 등 속성

삼각형의 세 정점 ABC 기준 

$$
\boxed{\lambda_A+\lambda_B+\lambda_C=1}
$$

$$
\boxed{
\mathbf{uv}_{f}
=\frac{
\displaystyle\sum_{i\in\{A,B,C\}}
\lambda_i\,\mathbf{uv}_i/w_i
}{
\displaystyle\sum_{i\in\{A,B,C\}}
\lambda_i/w_i
}}
$$

> 화면 좌표로 변환된 삼각형 내부에는 유한한 수의 픽셀 샘플이 존재한다. Rasterization은 각 샘플이 삼각형에 포함되는지 판정하고, 포함된 위치에 대해 세 정점의 Barycentric Coordinates를 계산한다.

이후 정점별 UV, Normal, Color 등의 속성을 보간한다. 원근 투영으로 발생하는 왜곡을 방지하기 위해 일반적으로 각 정점의 Clip Space \(w\)를 이용한 원근 보정 보간을 적용한다.

이렇게 계산된 속성은 Fragment Shader의 입력으로 전달된다.

- Fragment { P, depth, uv, N, Color ...}


## 4-6. Fragment Shader
- fragment의 보간된 UV, Normal, Color 등의 속성
- 쉐이더 리소스

$$
\boxed{
\mathbf C_f=
 f\!\left(
\operatorname{Texture}(\mathbf{uv}_f),
\mathbf n_f,\mathbf l,\text{material},\ldots
\right)
}
$$
> 사용자가 작성한 쉐이더 코드로 색상 등을 계산


- 색상 출력값 C
- { r, g, b, a }
